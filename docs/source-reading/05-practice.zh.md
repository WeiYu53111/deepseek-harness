## 开发时的判断方法

阅读每个机制时，检查谁作决定、程序保证什么，以及失败后留下什么状态。下面三组区别适用于工具调用、恢复和取消的设计。

| 区分 | 示例 | 开发者需要处理的内容 |
|---|---|---|
| 模型决策与程序保证 | 模型选择读取哪个文件；程序执行路径权限检查 | 参数校验、权限、取消和资源限制 |
| 模型描述与执行事实 | “文件已修改”需要工具结果和实际内容支持 | 可观察的执行记录与结果验证 |
| 可重试读取与有副作用操作 | 查询通常可以重试；发送请求超时后可能已经生效 | 幂等、重复执行和结果未知 |

例如“修复测试”可以涉及读取文件、修改代码、运行测试和根据结果继续修改。需要逐步检查读取失败、输出过大、测试持续失败以及用户取消等情况，不能仅凭模型给出完成文字判断任务成功。

## 练习与自测

下一轮打开 [agent-loop 实现](../../packages/core/agent-loop/src/agent.ts)，找到 `turn()` 和 `step()`。先跟踪正常完成路径，再阅读错误与取消路径，避免一次展开全部辅助函数。

1. 找出下一步由什么触发，以及工具结果如何进入后续模型上下文。
2. 区分一次模型请求及其工具执行，与包含多个步骤的一轮任务。
3. 找出停止条件，并解释工具执行失败时模型是否还能继续。
4. 选读 headless runner：解释为什么不能仅等待一次 `agent.whenIdle()` 就输出最终结果。

自测第 4 题的要点：子任务仍可能运行或唤醒父 Agent，因此需要等待相关子任务并重新检查父 Agent 状态及日志位置。

实践目标是实现一个支持工具调用、执行记录、取消和步数限制的单 agent。为它准备十几个具体任务，记录目标是否完成、是否发生越权行为、失败信息是否明确，以及请求次数、耗时和费用。单元测试检查程序逻辑，任务评测检查用户目标；该练习尚未实施。
